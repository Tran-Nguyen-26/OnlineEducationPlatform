# M7 private Java Spring Boot → Python FastAPI contract (in progress)

**Status:** Functional scope and public path agreed. The student service-assertion verifier in Python, issuer and authorized public proxy in core LMS, private status/conversation/history/send handlers, and asynchronous index worker are implemented and tested with disposable PostgreSQL and mocked providers. Live Java-to-Python and provider validation remain open. Public requests go to Spring Boot at `/api/courses/{courseId}/ai/...`, matching the live gateway's `/api/courses/**` pattern; the browser never calls these private paths. Public success schemas are in [`m7-ai-tutor.yaml`](../openapi/m7-ai-tutor.yaml). Its draft error envelope still needs reconciliation with Spring's live `application/problem+json` format. The first release returns a completed JSON chat response, with SSE retained as a later functional enhancement.

## Responsibilities

1. Spring Boot authenticates the end-user JWT and checks Student role, `PUBLISHED` course, `ACTIVE` enrollment, non-`UPCOMING` course phase and no `IN_PROGRESS` quiz in that course on **every** M7 request, including status, history and replay. Retrieval uses only current `AVAILABLE` learning content of supported formats in lessons currently unlocked for that Student; there is no per-lesson AI switch. Instructors and Admin receive no M7 access. Spring derives `user_id` from the authenticated principal. If an authoritative check is unavailable, fail closed with 503.
2. The core LMS Spring Boot service sends a private request to M7 with a dedicated HS256 service assertion after its live authorization checks. Its secret is distinct from the public end-user JWT key and is supplied to both services as `AI_TUTOR_SERVICE_JWT_SECRET` (at least 32 UTF-8 bytes). Never accept a browser-supplied user/course header as identity.
3. FastAPI validates the assertion, compares its course claim with the path and enforces conversation owner/course on reads, writes and deletes. A foreign conversation ID returns 404. FastAPI owns RAG, persistence and provider adapters; it must not read the public end-user JWT as its only service credential.
4. Spring Boot forwards a valid public `X-Request-Id` UUID or generates one when absent, and forwards the required UUID-v4 `Idempotency-Key` unchanged on send. It maps recognized M7 error codes to its public ProblemDetail envelope without exposing internal text and never retries a send with a new key. Live Java/Python process verification remains pending.

## Student assertion contract

- `Authorization: Bearer <internal-jwt>` and `X-Request-Id: <UUID>` are required on every private student route. The token uses HS256 with `iss=oep-core-lms`, `aud=m7-ai-tutor`, `scope=ai:student`, and required `sub` (verified Student UUID), `course_id` (verified course UUID), `request_id` (same UUID as the header), `jti` (unique UUID), and integer-second `iat`, `nbf`, `exp` claims.
- The token lifetime is positive and at most 60 seconds; `nbf` cannot precede `iat`. FastAPI accepts at most three seconds of clock skew and requires the token course to match `{courseId}`. A missing, malformed, expired, incorrectly signed or mismatched assertion returns 401 before business logic. FastAPI does not accept the public user JWT as a substitute.
- The Java proxy now checks Student role, `PUBLISHED` course, `ACTIVE` enrollment, non-`UPCOMING` phase and same-course quiz state before minting a fresh assertion on every request. The proxy and issuer are disabled by default. Enabling them requires `AI_TUTOR_ENABLED=true`, a dedicated `AI_TUTOR_SERVICE_JWT_SECRET` and a non-empty `AI_TUTOR_BASE_URL` for the private service. Deployment secret provisioning, rotation procedure and indexing-service scope remain pending. No private route is publicly exposed.
- The live backend has `SEQUENTIAL` lesson locks. Core LMS computes the authoritative readable-lesson ID list with the same service used by its Student outline and protected content. For private **send-message** requests, Spring adds `readable_lesson_ids` to the private JSON body (never to the public request) and signs a `lesson_scope_sha256` claim in the student assertion. The claim is lowercase hex SHA-256 of lowercase canonical UUID strings, sorted lexicographically and joined with `\n` (no trailing newline); an empty list hashes the empty string. Python rejects absent, malformed, duplicate or digest-mismatched IDs and uses only those IDs in vector search and final citation validation. Other private student routes use an unscoped assertion after Spring checks access.

## Proposed private routes

All routes below use the private service origin, require the signed service assertion, and are never added to a public gateway route. Request bodies, pagination parameters and successful JSON response shapes match the corresponding public operation in the OpenAPI unless explicitly noted.

The private send-message body extends the public `SendMessageRequest` with required `readable_lesson_ids: UUID[]`. Spring alone populates this field from `AiTutorAccessPolicy.requireAuthorizedLessonScope`; browser-supplied lesson IDs are ignored. Python calls `require_signed_lesson_scope` on that field before any source query. A missing or mismatched signed scope returns 401; an authentic empty scope yields no retrievable lessons and cannot fall back to other course content. Both implementations use the same fixed digest test vector (`11111111-1111-4111-8111-111111111111`, `22222222-2222-4222-8222-222222222222` → `a22ad13a7d741402a16b943ba95a73481dfdbcece26d55a1e987bc81bec9b89b`).

| `POST /courses/{courseId}/ai/conversations` | `POST /internal/v1/ai/courses/{courseId}/conversations` | `createAiConversation` |
| `GET /courses/{courseId}/ai/conversations` | `GET /internal/v1/ai/courses/{courseId}/conversations` | `listMyAiConversations` |

The private conversation/history/send operations bind rows to the signed assertion's `sub` and `course_id` and return `AI_CONVERSATION_NOT_FOUND` (404) for a foreign, deleted or wrong-course conversation. Message reads return saved citation snapshots. Private status uses the latest source revision and queued/superseding jobs in the active `AI_TUTOR_EMBEDDING_SPACE_KEY`; it reports `NOT_READY`, `INDEXING`, `READY` or `DEGRADED` for the asserted course. Send requires the signed lesson scope, a UUID-v4 idempotency key, current source evidence and server-validated citations; missing evidence produces a citation-free `ABSTAINED` turn, while no queryable source yields `AI_INDEX_NOT_READY` (409).

The private indexing job create/read operations are implemented at `POST /internal/v1/ai/index-jobs` and `GET /internal/v1/ai/index-jobs/{jobId}`. Spring can issue a 60-second HS256 indexing assertion with `iss=oep-core-lms`, `aud=m7-ai-tutor`, `sub=oep-core-lms`, `scope=ai:index`, UUID `request_id` matching `X-Request-Id`, UUID `jti`, and integer `iat`/`nbf`/`exp`. Python rejects Student assertions on these routes. The job body has only the stable event ID, content/course/lesson IDs, version and action; a duplicate event with the same body returns 200 and the original job, a new event returns 202, and conflicting event-ID reuse returns 409. M2 writes UPSERT events through its transactional outbox for eligible initial content and course publication. Its relay publishes `ai.index.requested` on `oep.events`; the M7 RabbitMQ consumer receives the same six-field JSON body and commits the idempotent job before acknowledging delivery. The separate asynchronous worker processes that durable receipt. Broker credentials and queue permissions secure this path separately from the signed HTTP fallback.

The separate `POST /internal/v1/ai/sources/{contentId}/deactivate` accepts `course_id`, `lesson_id`, and `version_number`, records a durable same-version tombstone, and excludes every revision of that content/version from PostgreSQL-backed retrieval before returning 204. It retries safely; remote vector cleanup failure returns 503 while PostgreSQL keeps old evidence excluded. With M7 enabled, Admin deletion commits `DELETING` before making this signed request, then finalizes only after 204; failure leaves content unavailable for retry. Eligible TEXT/citation-metadata edits and file replacement use `INVALIDATING` with the same acknowledgement. A new file upload grant is issued only after acknowledgement; verified completion commits the new source version and UPSERT outbox event together.

Course lifecycle changes use private `PUT /internal/v1/ai/courses/{courseId}/access` with the same `ai:index` assertion and required `course_version`/`active` JSON body. M2 commits the course status first and waits for 204; a failed call leaves its non-`PUBLISHED` status in place for same-target retry. M7 stores the highest course version, rejects an equal-version contradictory state, ignores older deliveries, denies all student routes for an inactive course and excludes its vectors and citations. Publication enqueues eligible content through M2's outbox; the M7 worker waits while a course is inactive and resumes after the newer activation.

Admin processing visibility is provided through M2's conditional `GET /api/admin/courses/{courseId}/ai/index-status` management route. M2's existing `/api/admin/**` security rule requires Admin, checks the course exists, and sends an `ai:index` assertion to M7's `GET /internal/v1/ai/courses/{courseId}/index-status`. The response contains content ID, version, source title, state, error code and timestamp only; it contains no source text, object key or storage URL. Admin can call `POST /api/admin/courses/{courseId}/ai/reconcile` to compare current eligible M2 content versions with M7-known jobs/revisions and enqueue missing or older versions in M2's transactional outbox. Recovery event IDs are stable per content/version and M7 deduplicates delivery. A ShedLock-protected M2 scheduler resends current versioned access for every course and audits published content daily at 04:00 by default; it continues after an individual course fails. Live Java-to-Python HTTP verification has covered Java-issued student/index assertions and basic status/conversation routes, but not a full M2 application run.

## M7 to M2 authoritative source read

M7 now has a private `GET /internal/v1/ai/sources/{contentId}` client; M2 implements the route only when AI Tutor is enabled. The executable contract is [`m7-m2-source.yaml`](../openapi/m7-m2-source.yaml). M7 sends the job's `course_id`, `lesson_id`, and `version_number` as required query parameters. It signs a fresh HS256 assertion with the dedicated shared secret, `iss=m7-ai-tutor`, `aud=oep-core-lms`, `sub=m7-ai-tutor`, `scope=ai:source:read`, UUID `jti`, and a UUID `request_id` matching `X-Request-Id`; its lifetime is at most 60 seconds. This direction uses a distinct issuer, audience and scope from Spring's index-job assertion. The endpoint is not routed by the public gateway.

M2 reads from its primary database and returns a snapshot only when the exact version still belongs to the requested course/lesson, the course is `PUBLISHED`, and the content is eligible and `AVAILABLE`. A foreign, stale or unavailable source returns 404. Inline TEXT is returned in `text_content`; PDF/Markdown/JSON receives verified filename/MIME/size metadata and a short-lived storage download URL. No raw object key is returned. The M7 worker rejects a response with a different source identity or malformed payload, bounds the file download, and rechecks M2 before activating the embedded revision. Chat also checks current M2 eligibility before generation and replay, and validates every cited chunk against current M7 rows inside the commit transaction. Live Java-to-Python process verification remains pending.

## Implemented proxy transport and remaining contract work

- The first release returns one JSON `ChatTurnResponse`. The original checklist's SSE remains a later functional enhancement. Before adding it, define event types, a final citation/usage event, terminal errors, disconnect behavior and `Idempotency-Key` replay on both sides.
- Spring returns `QUIZ_LOCKED` (409) before proxying when an attempt is `IN_PROGRESS` in the same course. Its proxy maps private `{error:{code}}` responses only when status and code agree: `AI_INDEX_NOT_READY` (409), `AI_CONVERSATION_NOT_FOUND` (404), `IDEMPOTENCY_CONFLICT` / `AI_REQUEST_IN_PROGRESS` (409), and `AI_PROVIDER_UNAVAILABLE` (503). Unknown/malformed responses, private 401/403 and transport failures become public `AI_TUTOR_UNAVAILABLE` (503), with internal details hidden. Spring uses the existing ProblemDetail public error envelope; the OpenAPI draft's nested public `error` schema must be corrected before marking the aggregate contract complete.
- Every private call includes `X-Request-Id`; send-message includes `Idempotency-Key`. The proxy uses a 2-second connect and 10-second read timeout and does not retry requests. It validates public JSON fields, page bounds and UUID-v4 idempotency keys. Indexing-service assertion scope, end-to-end timeout budget and retry mapping remain to be specified with their handlers. A coordinated secret-rotation procedure is needed before deployment.
