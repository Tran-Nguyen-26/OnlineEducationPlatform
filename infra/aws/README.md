# AWS infrastructure (Terraform)

Two independent stacks. Both put **CloudFront** in front (free HTTPS on `*.cloudfront.net`, CDN caching of `/assets/*`),
keep every database/broker private, and give the app S3 access through an IAM role (no access keys).
Validated with `terraform validate` (Terraform 1.9); `ec2-demo` has been applied on an AWS Free Plan account — see [DEPLOY_FREE_PLAN.md](DEPLOY_FREE_PLAN.md) (region `ap-southeast-2`, `c7i-flex.large`, credit-funded). `ecs-managed` has not been applied.

| | `ec2-demo` | `ecs-managed` |
|---|---|---|
| Purpose | cheap demo for the lecturer | production-shaped architecture (matches `CLOUD_ALIGNMENT.md`) |
| Compute | 1 × EC2 c7i-flex.large (4 GB + 2 GB swap), Docker Compose | ECS Fargate, 5 services (`core-lms`, `assessment`, `api-gateway` autoscaled; `worker`, `frontend` fixed), circuit-breaker rollback |
| Database | Postgres container (EBS) | RDS PostgreSQL (+ optional Multi-AZ, + optional read replica) |
| Cache / broker | Redis, RabbitMQ containers | ElastiCache Redis, Amazon MQ (RabbitMQ) |
| Files | S3 | S3 |
| Secrets | generated by Terraform, written to the instance | Secrets Manager → injected into tasks |
| Rough cost | ≈ US$2–3/day (paid from Free Plan credit; destroy after the demo) | ≈ US$150–200/month *(infra-only baseline at low egress; full Production FinOps incl. `ai-tutor`, LLM tokens & 8 TB video egress PA-A vs PA-B: see [BRD v1.4 §7.2](../../docs/BRD_Project8_OEP_v1.4.md))* |

## Prerequisites
```bash
aws configure                      # an IAM user/role allowed to create the resources above
terraform -version                 # >= 1.5   (or:  docker run --rm -it -v "$PWD":/w -w /w hashicorp/terraform:1.9 ...)
```

## A. `ec2-demo`
```bash
cd infra/aws/ec2-demo
terraform init
terraform apply -var 'repo_url=https://github.com/<you>/<repo>.git' -var 'repo_branch=build/deploy-prep'
terraform output url                       # open it after ~10 minutes (first Docker build runs on the instance)
terraform output -raw admin_password       # admin@oep.local, must change on first login
aws ssm start-session --target "$(terraform output -raw instance_id)"   # shell without SSH; log: /var/log/oep-bootstrap.log
terraform destroy                          # after the demo
```

## B. `ecs-managed`
```bash
cd infra/aws/ecs-managed
terraform init
terraform apply -target=aws_ecr_repository.svc        # 1) create the registries first
../../../backend/scripts/push-ecr.sh <region> latest   # 2) build and push the 5 images
terraform apply                                        # 3) everything else (RDS/MQ take ~10-15 min)
terraform output url
```
Release: run the **Deploy** GitHub workflow (or push a new tag and `terraform apply -var image_tag=<tag>`); a failing deployment rolls back automatically
(ECS deployment circuit breaker). Scale-out for `core-lms-service`, `assessment-service`, and `api-gateway` is automatic (CPU 60 %, 1–4 tasks).

## Before the demo
- Upload a lesson video and a submission file from the UI (verifies S3 CORS + presigned URLs).
- Admin → *Vận hành*: outbox 0 failed, DLQ 0. `GET /actuator/health/readiness` is only reachable inside the VPC (port 9090).
- `terraform destroy` when finished: NAT gateway, RDS, MQ and the ALB bill per hour.

## Known limits (be honest in the report)
- Redis uses AUTH + TLS in transit (ElastiCache replication group, single node, no automatic failover).
- CloudFront → origin uses HTTP inside AWS (origin is locked to CloudFront's prefix list); use an ACM certificate + HTTPS listener with a real domain for production.
- Single NAT gateway and single-instance MQ: one AZ failure causes downtime. Set `multi_az=true` and add NAT/MQ redundancy for real HA.
- No WAF, no custom domain, no remote Terraform state (add an S3 backend + DynamoDB lock for team use).
